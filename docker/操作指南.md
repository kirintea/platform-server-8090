# Docker 本地依赖栈操作指南

本文档说明如何启动本地依赖栈（OTel Collector + Jaeger + Prometheus + Loki + Grafana + Redis + PostgreSQL）并验证部署状态。

---

## 前置条件

| 项 | 要求 | 验证命令 |
|----|------|---------|
| Docker Engine | 已安装并运行 | `docker info` |
| docker-compose | v1.21+ 或 v2+ | `docker-compose version` 或 `docker compose version` |
| 磁盘空间 | ≥ 3 GB（镜像） | — |
| 端口可用 | 3000/3100/4317/4318/5432/6379/8889/9090/16686 | `netstat -ano \| findstr :4317` |
| Python 3.12+ | 用于运行验证脚本 | `python --version` |

> 💡 **版本兼容说明**：
> - `docker-compose.yaml`（version 3.8）：适用于 **docker-compose v2+**（如 v2.26.1）
> - `docker-compose.legacy.yaml`（version 2.2）：适用于 **docker-compose v1.21+**（旧版独立命令）
> - 服务器上两个版本可共存，根据 `docker-compose --version` 输出选择对应文件

## 步骤 1：配置 Docker 镜像加速器（必做）

> ⚠️ **网络问题**：当前环境直连 `registry-1.docker.io` 会失败（`EOF` 错误）。必须先配置镜像加速器。

### 1.1 修改 daemon.json

编辑文件（Docker Desktop 用户）：

```
%USERPROFILE%\.docker\daemon.json
```

完整内容（保留原有配置，追加 `registry-mirrors`）：

```json
{
  "builder": {
    "gc": {
      "defaultKeepStorage": "30GB",
      "enabled": true
    }
  },
  "experimental": false,
  "registry-mirrors": [
    "https://docker.1panel.live",
    "https://docker.m.daocloud.io",
    "https://hub-mirror.c.163.com",
    "https://mirror.ccs.tencentyun.com"
  ]
}
```

### 1.2 重启 Docker Desktop

- 右键托盘 Docker 图标 → **Restart**
- 或命令行（管理员 PowerShell）：
  ```powershell
  Restart-Service com.docker.service
  ```

### 1.3 验证镜像加速器生效

```powershell
docker info --format "{{json .RegistryConfig.Mirrors}}"
```

期望输出包含配置的镜像地址列表（非空数组 `[]`）。

## 步骤 2：启动 Docker 栈

### 2.1 进入 docker 目录

```powershell
cd d:\temp\temp_2026_07\platform-server-2\platform-server-2\docker
```

### 2.2 拉取镜像并启动

**方式 A：docker-compose v2+（新版）**

```powershell
docker-compose up -d
```

**方式 B：docker-compose v1（旧版，如 1.21.0）**

```powershell
docker-compose -f docker-compose.legacy.yaml up -d
```

首次启动会拉取 7 个镜像（约 2 GB）：

| 镜像 | 大小（约） | 用途 |
|------|----------|------|
| `otel/opentelemetry-collector-contrib:latest` | 200 MB | 数据接收分发 |
| `jaegertracing/all-in-one:latest` | 350 MB | Trace 存储+UI |
| `prom/prometheus:latest` | 250 MB | Metrics 存储 |
| `grafana/loki:latest` | 200 MB | Logs 聚合 |
| `grafana/grafana:latest` | 400 MB | 可视化 |
| `redis:7-alpine` | 40 MB | 会话状态持久化（maxmemory 256mb + LRU） |
| `bitnami/postgresql:latest` | 200 MB | 对话历史 + 用户元数据 |

> 💡 若已导入离线镜像包，可免去网络拉取：
> ```powershell
> # 可观测性栈（5 个镜像）
> docker load -i exports/otel-stack-images.tar
> # Redis + PostgreSQL（2 个镜像）
> docker load -i exports/redis-postgres-images.tar
> ```

> 💡 若拉取过程中断，可重复执行启动命令，已下载的层会复用。

### 2.3 查看启动状态

```powershell
docker-compose ps
```

期望所有服务状态为 `Up`：

```

jaeger-dev             Up                  0.0.0.0:16686->16686/tcp

```powershell

```

## 步骤 3：验证部署状态

### 3.1 运行 PowerShell 健康检查脚本

```powershell
powershell -ExecutionPolicy Bypass -File verify_stack.ps1
```

脚本会执行 9 类检查（聚焦可观测性栈）：

1. docker-compose 可用性
2. 配置文件存在性（4 个 yml）
3. 5 个可观测性容器运行状态（OTel/Jaeger/Prometheus/Loki/Grafana）
4. 7 个端口可访问性
5. OTel Collector `:8889/metrics` 健康端点
6. Jaeger `:16686/api/services` API
7. Prometheus `:9090/-/healthy`
8. Loki `:3100/ready`
9. Grafana `:3000/api/health`

> ⚠️ `verify_stack.ps1` 当前仅检查可观测性栈 5 个容器。Redis / PostgreSQL 容器需单独验证：
> ```powershell
> # Redis
> docker exec redis-dev redis-cli ping   # 期望 PONG
> # PostgreSQL
> docker exec postgres-dev pg_isready -U user -d ragdb  # 期望 "accepting connections"
> ```

**成功输出示例**：

```
[STEP] 检查 docker-compose 命令...
[OK]   docker-compose 版本: 5.1.1
[STEP] 检查配置文件...
[OK]   找到: docker-compose.yaml
[OK]   找到: otel-collector-dev.yaml
...
==========================================
验证完成: 22 / 22 项通过
==========================================
```

### 3.2 访问可视化界面

| 服务 | 地址 | 默认账号 |
|------|------|---------|
| Jaeger UI | http://localhost:16686 | 无需登录 |
| Grafana | http://localhost:3000 | admin / admin |
| Prometheus | http://localhost:9090 | 无需登录 |

### 3.3 在 Grafana 中添加数据源（首次使用）

1. 登录 Grafana → **Connections** → **Data sources** → **Add data source**
2. 添加以下数据源：

| 数据源 | Type | URL |
|--------|------|-----|
| Jaeger | Jaeger | `http://jaeger:16686` |
| Prometheus | Prometheus | `http://prometheus:9090` |
| Loki | Loki | `http://loki:3100` |

> 💡 容器之间使用服务名通信（如 `jaeger`、`prometheus`、`loki`），不要用 `localhost`。

## 常见问题排查

### Q1：镜像拉取失败（EOF / timeout）

**症状**：`docker-compose up` 时出现 `EOF`、`Retrying in X seconds`、`i/o timeout`

**解决**：

1. 确认已按步骤 1 配置镜像加速器
2. 重启 Docker Desktop 后重试
3. 单独拉取镜像查看具体错误：
   ```powershell
   docker pull prom/prometheus:latest
   ```
4. 若仍失败，尝试使用镜像源全路径：
   ```powershell
   docker pull docker.1panel.live/prom/prometheus:latest
   docker tag docker.1panel.live/prom/prometheus:latest prom/prometheus:latest
   ```

### Q2：端口被占用

**症状**：`Bind for 0.0.0.0:4317 failed: port is already allocated`

**解决**：

1. 查找占用进程：
   ```powershell
   netstat -ano | findstr :4317
   ```
2. 停止占用进程，或修改 `docker-compose.yaml` 中的端口映射

### Q3：OTel Collector 启动失败

**症状**：`otel-collector-dev` 容器不断重启，日志报 `unknown type: "loki"`

**解决**：

1. 查看日志：
   ```powershell
   docker logs otel-collector-dev
   ```
2. 常见原因及修复：
   - **`loki` exporter 不可用**：`otel/opentelemetry-collector-contrib` v0.122+ 已移除原生 loki exporter，需改用 `otlp_http/loki` 通过 Loki 的 OTLP 端点推送日志
   - **exporter 名称弃用**：`otlp` 应改为 `otlp_grpc`，`otlphttp` 应改为 `otlp_http`
   - 配置语法错误
3. 验证 YAML 格式：
   ```powershell
   python -c "import yaml; yaml.safe_load(open('docker/otel-collector-dev.yaml'))"
   ```
4. 修改后重启容器：
   ```powershell
   docker-compose up -d --force-recreate otel-collector
   ```

### Q4：verify_trace.py 报错 "Jaeger API 未就绪"

**解决**：

1. 确认 Jaeger 容器运行：`docker ps | findstr jaeger`
2. 等待 30 秒后重试
3. 手动验证 API：浏览器打开 http://localhost:16686/api/services

### Q5：verify_stack.ps1 报解析错误（缺少 Catch/Finally、字符串缺少终止符）

**症状**：运行 `powershell -ExecutionPolicy Bypass -File verify_stack.ps1` 时报多个 `ParserError`，错误行号与实际代码不匹配

**原因**：脚本包含中文注释，但文件缺少 UTF-8 BOM。Windows PowerShell 5.x 默认按系统区域编码（GBK）读取，中文字符被误解导致解析器错位。

**解决**：为文件添加 UTF-8 BOM：
```powershell
$path = "docker\verify_stack.ps1"
$content = [System.IO.File]::ReadAllBytes($path)
$bom = [byte[]]@(0xEF, 0xBB, 0xBF)
[System.IO.File]::WriteAllBytes($path, $bom + $content)
```

### Q6：Jaeger 中找不到 Trace

**解决**：

1. 检查 Agent 端 OTLP endpoint 是否为 `http://localhost:4317`
2. 检查 OTel Collector 日志是否收到数据：
   ```powershell
   docker logs otel-collector-dev | findstr "traces"
   ```
3. 确认 Jaeger 服务名搜索正确（脚本使用 `verify-trace-script`）

### Q7：服务器上 docker-compose 版本不兼容

**症状**：旧版 docker-compose（如 1.21.0）报 `unsupported version` 或 `Additional properties are not allowed`

**解决**：

1. 确认版本：`docker-compose --version`
2. 使用 legacy 文件启动：
   ```bash
   docker-compose -f docker-compose.legacy.yaml up -d
   ```
3. legacy 文件已移除旧版不支持的字段：
   - `version` 降为 `2.2`
   - 移除 `volumes.*.name`（自定义 volume 名称）
   - 移除 `healthcheck.start_period`
   - `environment` 改为列表格式

## 停止和清理

### 停止服务（保留数据）

```powershell
cd d:\temp\temp_2026_07\platform-server-2\platform-server-2\docker
docker-compose stop
# 旧版 compose:
docker-compose -f docker-compose.legacy.yaml stop
```

### 停止并删除容器（Jaeger 内存数据会丢失）

```powershell
docker-compose down
# 旧版 compose:
docker-compose -f docker-compose.legacy.yaml down
```

### 彻底清理（包括镜像）

```powershell
docker-compose down --rmi all
```
